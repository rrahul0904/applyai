The current browser-worker boundary requires a human when it encounters CAPTCHA/security challenges. The implementation also classifies legal attestations, demographic questions, disability/veteran disclosures, background questions, and other sensitive unknown fields for explicit candidate action. ApplyAI must stop before making compensation commitments, legal attestations, signatures, or disclosure choices for a candidate. No login, CAPTCHA, or anti-bot control may be bypassed.

Required provider-specific acceptance before changing any `Hosted verified` value: exact release SHA, separate test account, provider Terms/policy review, supported form inventory, negative tests for unknown/sensitive questions and challenges, candidate-visible review, explicit approval, final receipt, and hosted browser evidence. No real charge or live application submission is permitted in automated tests.
